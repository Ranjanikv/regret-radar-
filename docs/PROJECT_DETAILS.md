# Regret Radar – Detailed Project Documentation

---

## 📚 Overview

**Regret Radar** is a hack‑athon‑style retail risk intelligence platform that unifies fragmented customer, product and store data inside **Exasol**.  It scores three primary risks per customer‑SKU‑store combination and presents an actionable, rupee‑valued **Regret Score**:

1. **Stock‑out risk** – lost revenue when a customer cannot purchase an item.
2. **Return‑margin erosion** – margin loss from reverse‑logistics.
3. **Silent churn signals** – early warning that a customer will stop buying.

The platform consists of:
- **Synthetic data generator** (`data_gen/`)
- **Exasol schema & analytical views** (`sql/`)
- **Python UDFs** (`udfs/`)
- **Data‑loading scripts** (`load/`)
- **Streamlit UI** (`app/`)
- **Tests & benchmarks** (`tests/`, `benchmarks/`)

All heavy computation (identity matching, forecasting, scoring, NLP) runs **inside Exasol** via **Python UDFs**.  The Python code outside the database is limited to orchestration, data loading and the interactive dashboard.

## ⚙️ Setup & Execution

### 1. Prerequisites
- **Windows 10/11** (PowerShell 5+).
- **Python 3.11** (use the `py -3.11` launcher).
- **Docker Desktop** (recommended) **or** **Podman** with a WSL 2 backend.
- **pyexasol**, **pandas**, **numpy**, **scikit‑learn**, **streamlit**, **ruff**, **pytest** – installed via `make setup`.

### 2. Install Python dependencies
```powershell
# From the repository root (D:\exasol)
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
ruff check .   # lint
```

### 3. Start Exasol (Docker preferred)
```powershell
# Ensure Docker Desktop is running as Administrator
docker run -d `
  --name exasol-nano `
  --shm-size=512m `
  --ulimit nproc=-1 `
  -p 8563:8563 `
  -v exasol-nano-data:/exa `
  docker.io/exasol/nano:latest
```
> The initial `SYS` password is printed in the container logs (`docker logs exasol-nano`).

If you prefer **Podman**, run the same command using `podman` after `podman machine init && podman machine start`.

### 4. Configure `.env`
Create a `.env` (copy from `.env.example`):
```
EXASOL_DSN=127.0.0.1:8563
EXASOL_USER=sys
EXASOL_PASSWORD=<the‑SYS‑password-from‑logs>
EXASOL_SCHEMA=REGRET_RADAR
```

### 5. Load synthetic data
```powershell
python -m load.init_regret_radar   # creates tables, loads CSVs generated by data_gen
```

### 6. Run the Streamlit dashboard
```powershell
streamlit run app/main.py
```
Open **http://localhost:8501**.  The landing page *Executive Risk Intelligence* now shows:
- Total regret exposure (rupees)
- KPI cards for each risk vector
- Top‑5 actionable interventions
- Risk‑composition pie chart, exposure bar chart, Pareto curve, store‑level heatmap.

## 📊 Core Data Model

### Tables (generated by `01_schema.sql`)
| Table | Primary keys | Important columns |
|-------|--------------|-------------------|
| `customers` | `customer_id` | `signup_date`, `segment` |
| `products`   | `sku_id`      | `category`, `price` |
| `stores`     | `store_id`    | `store_name`, `region` |
| `sales`      | `(customer_id, sku_id, store_id, txn_dt)` | `qty`, `price`, `revenue` |
| `support_tickets` | `ticket_id` | `customer_id`, `text`, `created_at` |
| `returns` | `return_id` | `customer_id`, `sku_id`, `store_id`, `loss_amount` |

### Views (exposed to the UI)
- **`v_regret_score`** – aggregates per `customer_id, sku_id, store_id` the three loss columns (`stockout_loss`, `return_loss`, `churn_loss`) and computes `regret_score_rupees = stockout_loss + return_loss + churn_loss`.
- **`v_action_queue`** – same granularity as `v_regret_score` plus the derived fields `dominant_risk` (the largest loss component) and `suggested_intervention`/`reason` (rule‑based text generated by the UDFs).

## 🧩 UDFs (Python inside Exasol)
| UDF file | Purpose | Input mode |
|----------|---------|-----------|
| `identity_scorer.py` | Probabilistic identity resolution using a graph‑connected‑components approach. | **SET**, returns a table of merged `customer_id` groups. |
| `stockout_forecaster.py` | Time‑series forecast (ARIMA‑like) of daily demand; predicts stock‑out probability. | **SCALAR**, returns a numeric probability per SKU‑store.
| `return_scorer.py` | Rule‑based margin‑loss estimator derived from return‑reason templates. | **SCALAR**, returns expected loss in rupees.

All UDFs follow the required signature `def run(ctx): ...` and are tested with `exasol-udf-mock-python` (see `tests/test_udfs_mock.py`).

## 🐞 Known Issues & Work‑arounds
| Issue | Symptom | Work‑around |
|-------|---------|------------|
| Docker Desktop fails to start (pipe ACL) | `Access is denied` to `\\.\pipe\docker_engine` | Run Docker Desktop **as Administrator** or follow the reset steps in the troubleshooting section above. |
| `sku_id` appears as `NULL` in the Action Queue | Missing join to `products` view for some SKUs | Verify that `sku_id` is populated in the `products` table (run `SELECT COUNT(*) FROM products WHERE sku_id IS NULL`). |
| Churn dominates top actions | Churn model currently uses a simple rule‑based heuristic that may over‑score | Retrain the churn predictor on a larger synthetic set or adjust the threshold in `churn_scorer.py`. |
| Intermittent `pyexasol` `EPERM` on Windows | Transient folder‑creation permission issue | Re‑run the failing command up to two times (the error is usually transient). |
